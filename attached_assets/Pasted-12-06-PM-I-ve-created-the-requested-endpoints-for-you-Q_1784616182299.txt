To use the new endpoint you just need to pass the questionId and targetLanguage. Since the backend handles fetching the question texts and saving the translations directly to the database, your frontend code actually becomes much simpler!

Here is how you can update your handleTranslate function in 

questions.tsx
 to use the new endpoint:

typescript
const handleTranslate = async (q: Question) => {
  // If they select English, we just clear the translated state
  if (targetLang === 'en') {
    setTranslations(prev => {
      const next = { ...prev };
      delete next[q.id];
      return next;
    });
    return;
  }
  setTranslatingId(q.id);
  try {
    // Call the new endpoint, passing only the questionId and targetLanguage
    const res = await fetch('/api/translate-question', {
      method: 'POST',
      headers: { 
        'Content-Type': 'application/json', 
        Authorization: `Bearer ${token}` 
      },
      body: JSON.stringify({ 
        questionId: q.id, 
        targetLanguage: targetLang 
      }),
    });
    if (!res.ok) {
      const err = await res.json().catch(() => ({}));
      throw new Error(err.details || err.error || 'Translation failed');
    }
    const data = await res.json();
    
    // Update the UI with the translated text returned from the backend
    setTranslations(prev => ({
      ...prev,
      [q.id]: {
        question: data.translated.questionTranslated,
        explanation: data.translated.explanationTranslated,
        options: data.translated.optionsTranslated,
        correctAnswer: data.translated.correctAnswerTranslated,
      }
    }));
    // The backend also automatically updated the question in the database!
  } catch (err: any) {
    console.error(err);
    alert(`Translation failed: ${err.message}`);
  } finally {
    setTranslatingId(null);
  }
};
Key Differences:
No need to pack strings: You no longer need to extract textsToTranslate from the question. The backend pulls the full text directly from the database using the questionId.
Returns an object: The backend now returns a data.translated object containing questionTranslated, explanationTranslated, optionsTranslated, and correctAnswerTranslated, instead of just an array of strings.
Persists automatically: The translation is now automatically saved to Firestore under fields like questionTranslated and translatedLanguage for that specific question.

The two new endpoints I created are ready to be used. Here are their exact details so you can test them or integrate them:

1. Question Translation Endpoint
This endpoint translates a question and saves the translation directly to your database.

URL: POST /api/translate-question (or just /translate-question if you are calling the backend directly)
Headers:
Content-Type: application/json
Authorization: Bearer <your-token>
Body:
json
{
  "questionId": 12345,
  "targetLanguage": "hi"
}
(The targetLanguage should be the language code, like "hi" for Hindi, "gu" for Gujarati, "fr" for French, etc.)

2. API Chat Endpoint
This is a general-purpose chat endpoint you can use to talk directly with your active AI provider.

URL: POST /api/chat (or just /chat if calling the backend directly)
Headers:
Content-Type: application/json
Authorization: Bearer <your-token>
Body:
json
{
  "message": "Write a 2 sentence summary of photosynthesis.",
  "systemPrompt": "You are a helpful science tutor." 
}
(Note: systemPrompt is optional. If you don't provide it, it defaults to "You are a helpful AI assistant".)
